PART 1 REST API

All REST endpoints are served under the base path /api and communicate in JSON. Most endpoints require eWater credentials to be configured first (see Credentials below). Unauthenticated requests receive 401 { "error": "No credentials configured" }. Upstream eWater API errors are proxied back as 502 { "error": "eWater API error: …" }.

Credentials

GET /api/ewater/credentials

Check credential status

Returns whether eWater credentials are configured and when the session token expires.

{ "isConfigured": true, "environment": "live", "tokenExpiresAt": "2026-08-04T16:00:00Z" }

POST /api/ewater/credentials

Save eWater credentials

Stores credentials and validates them by obtaining a session token immediately. Returns 401 when credentials are invalid.

Body: { "username": "user@example.com", "password": "…" }

DELETE /api/ewater/credentials

Clear saved credentials

Removes stored credentials and invalidates the session. Subsequent API calls return 401.

Assets

GET /api/ewater/assets

List all assets

Returns every asset (community taps, controllers, eSENSE sensors) visible to this account. Fields: id, name, type, status, isOnline, batteryVoltage, waterSystemName, countryName.

GET /api/ewater/assets/:assetId

Get asset details

Full detail for one asset: basic info, health status, connectivity, and power — fetched in parallel from the eWater State and Query APIs.

NameIn / TypeRequiredDescription
assetIdpath · stringrequiredNumeric asset ID

GET /api/ewater/assets/:assetId/tech

Comprehensive technical status bundle

Aggregates all technical data for one asset in a single call (12 upstream requests in parallel): connectivity, power, flow, usage, status values, firmware, identifiers, recent commands, EWC settings, and entity hierarchy for water system / country resolution. Primary endpoint used by the asset detail page.

Key fields: lastCommsDt, batteryVoltage / batteryTrend / batteryTodayHigh / batteryTodayLow, flowRateHour / flowRateToday / flowRateWeek, litresDispensedToday, imeis[], firmware[], healthFlags, tamperSwitchState, ewcFcf / ewcLcf / ewcFx / ewcPreload / priceOfWater.

GET /api/ewater/assets/:assetId/ewc

EWC calibration settings

Returns the Electronic Water Controller device configuration: FCF, LCF (ticks per litre — the calibration factor), currency/FX, preload, price per litre, and all other EWC parameters.

GET /api/ewater/assets/:assetId/esense-charts

eSENSE time-series charts

Chart data for eSENSE tank-level assets over a configurable window.

NameIn / TypeRequiredDescription
assetIdpath · stringrequiredNumeric asset ID
daysquery · integeroptional (default 3)Days to look back

Response includes: tankHeight[] (water & chlorine depth with min/max bands), dailyInflow[] (litres per day), voltageHistory[], voltageStatus, flowRateHistory[] (per-dispense L/min), dispenseVolumes (histogram + KDE curve + suggested LCF calibration model).

GET /api/ewater/assets/:assetId/meter-reading

Tick accumulator meter reading

Extracts the lifetime tick accumulator from the most recent HEALTH_STATE (0x19) EWC packet in the last 14 days and converts it to litres using the asset's LCF.

Response: { ticks, lcf, litres, timestamp, found }. found: false = no HEALTH_STATE packet received recently.

GET /api/ewater/assets/:assetId/flow-rate

Most recent flow rate

Most recent valid dispense flow rate (L/min) from EWC logs in the last 24 hours.

Response: { flowRate, timestamp, timedOut }. timedOut: true = no dispense in 24 h.

GET /api/ewater/assets/:assetId/telemetry

Raw telemetry log

Last 50 raw telemetry entries for an asset (last 7 days), newest first. For fully decoded entries use /logs.

Calibration

POST /api/ewater/assets/:assetId/detect-sensor-range

Auto-detect eSENSE sensor range

Correlates recent VSEN ADC readings from EWC packets with the eWater tank-height API to back-calculate the sensor's full-scale range in metres. Persists the result for use by alert rules.

Response: { sensorRangeMetres1, sensorRangeMetres2, sensorRangeMetres3, vsen1, vsen2, vsen3, depthMetres1, timeDeltaSeconds }. Returns 422 when no sensor data is available.

POST /api/ewater/assets/:assetId/apply-calibration

Write LCF + Preload to device

Sends RequestSettingChange to the eWater Command API for both LitresConversion and Preload. The device applies changes on its next comms cycle.

Body: { "lcf": 512, "preload": 0 } — both integers.

Response: { success, results: [{ settingKey, success, error }] }.

POST /api/ewater/assets/:assetId/reset-meter

Reset tick accumulator

Sends ResetTickAccumulator to the eWater Command API. IMEI is resolved automatically.

Body: { "litres": 15420.5 }   Response: { litres, success, error }.

PART 2 MCP Server

Overview & Authentication

The MCP server is exposed at POST/GET/DELETE /api/mcp using the Streamable HTTP transport (JSON-RPC 2.0). It provides the same data as the REST API as callable tools designed for LLM clients (Claude, GPT-4, WhatsApp AI agents, etc.). The server is stateless — a fresh server + transport is created per request.

Authentication

Authorization: Bearer <MCP_BEARER_TOKEN>

This is separate from the eWater credentials. Both must be configured: the bearer token protects the MCP endpoint itself; the eWater credentials (set via the REST API) are used by the tool implementations to reach live data.

Pagination Envelope

Every tool response uses the same envelope:

{
  "totalCount": 142,      // true total across all pages
  "returnedCount": 25,    // records in this response
  "offset": 0,
  "limit": 25,
  "hasMore": true,
  "items": [ … ]          // or named array: "assets", "tagIds", etc.
}

Single-object tools (get_asset_ewc_settings, get_asset_flow_rate, get_calibration_analysis) return their result under data with totalCount: 1, hasMore: false.

Typical Call Chain

get_tag(nfcId)
  → get_asset(primary_asset_id)                          // tap name, water system, country
  → get_household(household_id)                          // household name
  → get_disbursements_by_tag_and_asset(nfcId, assetId)   // water usage this month
  → get_asset_logs(assetId)                              // recent device activity

Log Tools

get_asset_logs

Fully-decoded device communication logs, newest first. Critical: the pipeline field identifies direction — MQTT/UDP = incoming telemetry from the device; CmdApi = outgoing command, NOT incoming data. If all visible entries are CmdApi, the device is offline. Decoded fields include eventName, eventCategory, batteryVolts, flowTicks, litres, tagUid, vsen1-3 ADC (eSENSE), and more. Shengda NB-IoT frames include a plain-language description field.

Inputs:

NameIn / TypeRequiredDescription
assetIdstringrequiredNumeric asset ID
daysinteger 1–30optional (default 7)Days of logs to fetch
limitinteger 1–100optional (default 25)Max entries — use 10–25 for WhatsApp
beforeISO timestampoptionalCursor for pagination — timestamp of last entry from previous call
protocolstringoptionalInclude only: Ewc2_5 | CommandApi_1 | 4CCv1 | Gadwall
excludeProtocolsstring[]optionalProtocols to exclude, e.g. ["4CCv1"]

APPENDIX Pagination Envelope & Errors

Pagination Envelope

Used by all MCP list tools and the tag-usage REST endpoint:

FieldTypeDescription
totalCountintegerTrue total matching records across all pages — use this to answer count questions from a single call
returnedCountintegerRecords returned in this response
offsetintegerRecords skipped before the first result
limitintegerMax records per call as requested
hasMorebooleanTrue when records exist beyond this page
items / assets / tagIds…arrayThe records for this page, under a semantically named key

To iterate: increment offset by limit until hasMore is false.

400Invalid request body or parameters{ "error": "…" }
401No credentials configured (REST) or invalid bearer token (MCP){ "error": "…" }
404Asset / tag / household not found{ "error": "…" }
422Cannot compute result (e.g. no sensor data for range detection){ "error": "…" }

Key Concepts

TermDefinition
LCF (LitresConversion)Ticks per litre — the primary calibration factor. Divide raw flow-meter ticks by the LCF to get litres. Stored in EWC settings.
FCF (FlowConversion)Ticks per credit (prepay unit). Different from LCF. The packet trailer bytes[33–34] hold the FCF, not the LCF — always read LCF from EWC settings.
PreloadUnmetered tick offset at valve-open — ticks dispensed before the meter starts counting. Must be subtracted when calculating true volume.
pipelineCommunication direction in packet logs: MQTT/UDP = device → platform (incoming telemetry); CmdApi = platform → device (outgoing command).
VSEN1/2/3Analogue sensor ADC values (0–255) on eSENSE assets. ADC 51 ≈ 4 mA (sensor empty/off), ADC 255 ≈ 20 mA (sensor full). Convert to depth using sensor range from EWC settings.
NRWNon-Revenue Water — water dispensed that does not generate revenue, typically due to meter drift, miscalibrated LCF, or preload offset errors.
