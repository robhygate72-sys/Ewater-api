74. DEFINITION OF DONE

The feature is complete when all of the following are true:

- "/hhc" exists.
- The page contains Overview, Commissioning and Operations & Maintenance.
- Every displayed meter comes from the live eWater HouseholdMeter asset list.
- No runtime mock/sample meter data exists.
- Shengda data is decoded server-side.
- ICCID and IMEI are structured fields, not dependent on description-string scraping.
- Meter reading comes from Shengda.
- Prepaid allowance comes from Shengda.
- Battery and battery state come from Shengda where reported.
- Valve state comes from Shengda.
- RSRP/SNR come from Shengda.
- RTC comes from Shengda.
- Report cycle comes from Shengda.
- Error/magnetic states come from Shengda.
- Data freshness is visible.
- Three-communication commissioning validation works.
- QC workflow is persisted.
- Gate 1, Gate 2 and Gate 3 are represented.
- Gate 3 sampling is configurable as a percentage.
- No generic arbitrary command proxy is used by normal users.
- No unsupported Shengda write endpoint is invented.
- Unsupported controls remain disabled and clearly labelled.
- Verified writes are server-side, permissioned and audited.
- Accepted commands remain pending until device state confirms them.
- Manual water allocation never changes the balance locally.
- Missing API data renders as missing, not zero.
- OpenAPI schemas are updated.
- Generated API client/hooks are regenerated.
- TypeScript passes.
- Production build passes.
- Existing eWater monitoring features continue working.
